# Guitar MES 勤務終了プロンプト（完成版）

本日のGuitar MES開発を終了します。

これまでの会話、本日共有したファイル、昨日までの引き継ぎメモ、Git状態スナップショット、テスト結果、エラー対応、確定した運用ルールを確認し、以下の2つを作成してください。

## 【1. 今日のまとめ・引き継ぎメモ】

昨日までの引き継ぎメモが共有されている場合は、その内容を引き継いでください。

古くなった進捗、到達点、次回予定は、本日の実績に合わせて更新してください。過去の記載をそのまま残すのではなく、現在有効な情報へ整理してください。

### 含める内容

#### 作業内容

- 本日の概要
- 本日完了した作業
- 実装または更新した機能
- 新規作成、更新した主要ファイル

#### 設計・運用

- 確定した業務ルールと設計方針
- 本日確定した開発運用ルール

#### テスト

- テスト実績
- 通常テストの件数と結果
- 関連テストの件数と結果
- E2Eの件数と結果
- 未実行のテスト

各テストについて、確認できる場合は次を明記してください。

- テストクラスまたは対象範囲
- Tests run
- Failures
- Errors
- Skipped
- BUILD SUCCESSまたはBUILD FAILURE
- 実行日時
- ログファイル名

#### 問題対応

- 発生した問題
- 原因
- 対応内容
- 再発防止策

#### 進捗

- 現在のPhase
- 現在の到達点
- 未完了事項
- 注意事項

### Git状態

本日共有された `git_status_snapshot.txt` が存在する場合は、必ず確認してください。

次の内容を引き継ぎメモへ反映してください。

#### 現在ブランチ

`CURRENT BRANCH` の実際の出力を記載してください。

#### 作業ツリー状態

`STATUS` の結果を確認し、次のいずれかを明記してください。

- clean
- 未コミット変更あり
- 未追跡ファイルあり
- ステージ済み変更あり

変更や未追跡ファイルがある場合は、ファイル名を記載してください。

#### 最新コミット

次を記載してください。

- コミットハッシュ
- コミットメッセージ
- HEADが指しているブランチ

#### originとの同期状態

`git branch -vv` とコミット表示を確認し、次を明記してください。

- originの追跡ブランチ
- ローカルとoriginが同期済みか
- aheadまたはbehindがあるか

確認できない場合は「未確認」としてください。

#### mainとの差分状況

確認できる範囲で、次を記載してください。

- mainの最新コミット
- 現在ブランチの最新コミット
- 現在ブランチがmainへマージ済みか
- 現在ブランチで継続作業中か

情報が不足している場合は推測せず、「未確認」としてください。

#### ローカルブランチ一覧

`LOCAL BRANCHES` から主要ブランチを記載してください。必要に応じて、作業中、マージ済み、旧ブランチの候補を整理してください。

#### 次回作業予定ブランチ

次回作業を継続するブランチを記載してください。

#### マージ候補ブランチ

マージ可否が確認できるブランチのみ記載してください。確認できない場合は「未確認」としてください。

#### 削除候補ブランチ

マージ済みで削除可能と確認できるブランチのみ候補として記載してください。削除を断定せず、次回確認事項として扱ってください。

`git_status_snapshot.txt` が共有されていない場合は、「Git状態未共有」と明記してください。ブランチ名、コミット、同期状態を推測で補完しないでください。

### 次回用情報

- 次回開始時に確認すること
- 次回の推奨作業順序
- 次回必要になる可能性が高いファイル
- コミットメッセージ候補
- 次回チャット開始用ショートメモ

### 記載ルール

- 完了していない作業を完了済みと記載しないでください。
- テストを実行していない場合は「未実行」と明記してください。
- 推測で進捗、テスト件数、Git状態を補完しないでください。
- 同日の複数ログがある場合は、対象機能と実行順を区別してください。
- 修正前に成功した全件テストを、修正後の成功実績として扱わないでください。
- エラー後に再実行して成功した場合は、失敗内容と最終成功の両方を記載してください。
- 本日確定した運用ルールは、次回以降も使用できる形で明文化してください。

### 出力ファイル名

次の形式にしてください。

```text
yyMMdd_Guitar_MES_今日のまとめ・引き継ぎメモ.md
```

Markdownファイルとして作成し、そのままダウンロードできるリンクを提示してください。

## 【2. 勤務報告フォーム入力用文章】

Microsoft Formsの「行った資格取得以外の自己研鑽内容を具体的に記載してください」という自由記述欄へ、そのまま貼り付けられる文章を作成してください。

### 作成ルール

- 箇条書き、見出し、Markdown、コードブロックは使用しないでください。
- 自然な日本語の文章としてまとめてください。
- 業務日報ではなく、自己研鑽の報告として記載してください。
- 学習内容、技術的な取り組み、得られた知識、改善した点が伝わる表現にしてください。
- 専門用語を並べるだけではなく、何を目的に、何を実装または検証し、何を学んだかが分かる文章にしてください。
- 過大な表現は避け、実際に本日行った内容だけを記載してください。
- 文字数は300字から500字程度を目安にしてください。

## 最終出力順序

必ず次の順番で提示してください。

1. 作成した引き継ぎメモのダウンロードリンク
2. 勤務報告フォームへ貼り付ける文章
3. 本日の完了事項と未完了事項の短い確認

## 作業終了前に共有するGit状態スナップショット

作業終了前に、プロジェクト直下で次のコマンドを実行して作成した `git_status_snapshot.txt` を共有します。

```bash
{
  echo "===== CURRENT BRANCH ====="
  git branch --show-current

  echo
  echo "===== STATUS ====="
  git status --short

  echo
  echo "===== LOCAL BRANCHES ====="
  git branch -vv

  echo
  echo "===== LAST 20 COMMITS ====="
  git log --oneline --decorate -20

  echo
  echo "===== REMOTES ====="
  git remote -v
} > ~/Downloads/git_status_snapshot.txt
```

生成ファイル:

```text
~/Downloads/git_status_snapshot.txt
```

勤務終了時には、可能な限り次を共有してください。

- 前回の引き継ぎメモ
- `git_status_snapshot.txt`
- 当日のテストログ
- 当日のエラーログ
- 必要に応じて画面のスクリーンショット
